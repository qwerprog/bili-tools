## 变更说明

### 1. 新增 `bit video replace`：原地替换稿件视频
无需删除重投，直接替换已投递稿件中指定分P的视频文件，**保留 BV 号、播放、点赞、评论等全部稿件数据**，并可同时修改标题：

```bash
# 替换 P1 视频文件
bit video replace BV1xxxxxxxxx new.mp4

# 替换第 2P，并同时修改稿件标题
bit video replace BV1xxxxxxxxx new.mp4 -p 2 -t "新标题"

# 脚本 / AI Agent 非交互调用
bit --json -y video replace BV1xxxxxxxxx new.mp4
```

- **上传前预检**：先读取创作中心稿件详情，校验 `replace_check.can_replace`、分P序号范围与标题长度（≤ 80 字），避免大文件上传完成后才发现无法替换。
- **安全确认**：替换会触发稿件重新审核，交互模式下展示「稿件 · 分P · 新文件 · 新标题」并二次确认；`--json` / 非 TTY 下必须显式传入 `-y` 才会执行。
- **保留分P信息**：替换后沿用原分P标题与简介，其余分P、封面、分区、标签、简介、版权声明等元数据保持不变。
- **结构化输出**：`--json` 返回 `bvid`、`part`、`total_parts`、`part_title`、`old_filename`、`new_part`、`title_changed` 等字段，便于脚本串联。
- 支持与 `upload` / `append` 一致的 `-l/--line` 上传线路与 `--limit` 并发参数。

### 2. 稿件编辑接口重构
- 将 `/x/vu/web/edit` 的载荷构造与提交逻辑抽取为公共函数，`append`（追加分P）与 `replace`（替换分P）共用同一套实现，统一错误信息格式，后续扩展编辑能力更方便。

### 3. 一键脚本安装
- 新增 `install.sh`（Linux / macOS）与 `install.ps1`（Windows），自动识别系统与 CPU 架构并下载最新预编译二进制：

### 4. 文档与 Agent 插件同步
- README 快速使用与命令架构补充 `video replace`。
- Antigravity 插件技能（`SKILL.md` / `commands.md`）新增替换用法；安全规约（`AGENTS.md`）将 `video replace` 列入需用户明确确认的公开副作用命令。

### 5. 新增 B 站字幕上传、查询与删除
补齐字幕轨管理链路，支持把本地 SRT 转成 B 站字幕格式（BCC）提交到指定稿件的指定分P：

```bash
# 提交字幕到 P1（客户端 SRT→BCC，提交审核）
bit video subtitle-upload BV1xxxxxxxxx sub.zh.srt --lang zh -p 1

# 只存草稿 / 只做离线转换检查（不发任何请求）
bit video subtitle-upload BV1xxxxxxxxx sub.zh.srt --lang zh --draft
bit video subtitle-upload BV1xxxxxxxxx sub.zh.srt --lang zh --dry-run

# 查询分P字幕轨 / 账号全部字幕（含草稿与已删除）
bit video subtitle-list BV1xxxxxxxxx -p 1 --status all

# 删除字幕轨（软删除，条目 status 变为 4）
bit --json -y video subtitle-delete BV1xxxxxxxxx --id <SUBTITLE_ID> -p 1
```

- **SRT → BCC**：去 BOM、兼容 CRLF/CR、识别序号行、删除 `<...>` 样式标签、强制时间轴单调递增；没有可上传条目时直接报错，不会提交空字幕。
- **语言归一化**：上传侧只认基础 ISO 码（`en`、`zh`、`zh-Hant`、`ja`、`ko`）；`zh-Hans`、`zh-CN`、`en-US` 自动归一化并在输出中同时回显原始输入；白名单外的值在发请求前报 `Input`。
- **提交结果复核**：`draft/save` 的响应体不可信，提交后会轮询 `author/list` 确认新版本真的落库（实测索引延迟约 40 秒，默认最多等 90 秒）；未确认到就按失败报错，避免「接口 code=0 但没写入」的误报。
- **`--no-verify`**：跳过提交后的列表回查，供大批量补字幕使用（每次回查都要扫全账号字幕列表，上百条会显著变慢）；输出 `verified=false`，落库结果需自行用 `subtitle-list` 复核。
- **版本语义**：字幕绑定 cid（分P），同一 `(cid, lang)` 重复上传是新增版本而非覆盖，旧版本继续保留；完全相同的重复提交会被服务端静默去重，复核阶段会因此报错而不是误报成功。
- **查询稳定路径**：统一走 `author/list`，不使用真机上间歇性返回 `-400` 的 `search/list`；`--status all|draft|published|deleted` 在本地过滤（新条目在服务端索引中通常有几十秒延迟）。
- **删除语义**：软删除，条目 status 先变为 4，短时间内仍可在列表中看到，之后由服务端从列表移除。
- **安全确认**：`subtitle-delete` 在交互模式下展示字幕 ID / 语言 / 状态并二次确认；`--json` 或非 TTY 下必须显式 `-y`，且拒绝在任何网络请求之前发生。
- **结构化输出**：`--json` 上传返回 `bvid`/`aid`/`cid`/`page`/`lang`/`lang_input`/`entries`/`verified_id` 等字段，列表返回 `scope`/`cid`/`total`/`subtitles`，删除返回 `deleted` 与 `soft_delete`。
- 新增 `api::subtitle` 模块，并在 Windows 调试构建中放宽主线程栈（超大 clap 命令树加新子命令后可能触及 1MB 默认上限）。
